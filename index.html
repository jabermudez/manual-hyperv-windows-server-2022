Fundamentos

Qué vas a construir

Hyper‑V es la plataforma de virtualización de Microsoft. Permite ejecutar varios equipos virtuales aislados sobre un mismo equipo físico, compartiendo procesador, memoria, almacenamiento y red.

02
Antes de empezar

Requisitos del equipo anfitrión

Comprueba los requisitos antes de descargar archivos o crear la máquina virtual. Una preparación correcta evita la mayoría de los errores posteriores.

CPU

Procesador

64 bits, virtualización asistida por hardware y traducción de direcciones de segundo nivel (SLAT).

RAM

Memoria

8 GB como mínimo práctico; 16 GB o más recomendados para trabajar con comodidad.

SSD

Almacenamiento

Al menos 80 GB libres. Un SSD reduce de forma notable los tiempos de instalación.

OS

Sistema anfitrión

Windows 10/11 Pro, Enterprise o Education de 64 bits. Hyper‑V no está incluido en Home.

Comprobaciones rápidas

1

Abra Información del sistema

Presione Win + R, escriba msinfo32 y pulse Enter.

2

Revise los requisitos de Hyper‑V

Al final del resumen, las cuatro entradas de Hyper‑V deben indicar Sí.

3

Confirme la edición de Windows

Vaya a Configuración → Sistema → Acerca de → Especificaciones de Windows.

PowerShell · consulta del sistema
systeminfo.exe
Get-ComputerInfo | Select-Object WindowsProductName, WindowsVersion,
    CsTotalPhysicalMemory, HyperVisorPresent
!
Si la virtualización aparece deshabilitada

Reinicie el equipo, entre al firmware UEFI/BIOS y active Intel VT‑x/VT‑d o AMD‑V/SVM. El nombre exacto depende del fabricante.

Plataforma de virtualización

Instalar Hyper‑V en Windows

Método gráfico

Características de Windows

  1. Abra el menú Inicio y busque Activar o desactivar las características de Windows.
  2. Marque Hyper‑V y confirme que incluye Plataforma de Hyper‑V y Herramientas de administración.
  3. Pulse Aceptar, espere la instalación y seleccione Reiniciar ahora.
  4. Después del reinicio, abra Administrador de Hyper‑V.
Método PowerShell

Instalación automatizada

Abra PowerShell como administrador y ejecute:

Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All

Confirme el reinicio cuando el sistema lo solicite.

!
Importante

Guarde su trabajo antes de habilitar la característica: el reinicio es necesario para cargar el hipervisor.

Verificación

PowerShell · estado de Hyper-V
Get-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V-All
Get-Service vmms

Debe ver: State = Enabled y el servicio vmms en estado Running.

Conectividad

Crear el conmutador virtual

El conmutador virtual funciona como un switch de red por software. Define con quién podrá comunicarse la máquina virtual.

EX

Externo

Conecta la VM con la red física e Internet mediante la tarjeta del host.

Recomendado para este laboratorio
IN

Interno

Comunicación entre el host y las VM, sin acceso directo a la red física.

Útil para redes aisladas
PR

Privado

Solo comunica máquinas virtuales conectadas al mismo conmutador.

Máximo aislamiento

Monte la imagen ISO

8

Finalice y ajuste

1. Diseño y requisitos del laboratorio

Defina los nombres y direcciones antes de instalar el rol. Después de crear el bosque, cambiar el nombre DNS del dominio implica una migración compleja.

Servidor

DC01

  • Windows Server 2022 actualizado
  • 2 vCPU, 4 GB RAM y 60 GB de disco como mínimo de laboratorio
  • IP 192.168.10.10/24
  • Gateway 192.168.10.1
  • DNS preferido 192.168.10.10
Dominio

ad.empresa.example

  • NetBIOS: EMPRESA
  • Nivel de bosque: Windows Server 2016
  • Nivel de dominio: Windows Server 2016
  • DNS integrado en Active Directory
  • Contraseña DSRM diferente y protegida
Clientes

Dos Windows 11 Pro

  • PC-VENTAS01 · 192.168.10.21
  • PC-TI01 · 192.168.10.22
  • 2 vCPU, 4 GB RAM y 64 GB de disco
  • Mismo conmutador virtual que DC01
  • DNS: únicamente 192.168.10.10
!
Edición del cliente

Windows Home no puede unirse a un dominio de Active Directory local. Use Windows 10/11 Pro, Enterprise, Pro Education o Pro for Workstations.

Producción

Use un subdominio de un nombre DNS que controle la organización. .local puede entrar en conflicto con mDNS; .example se utiliza aquí solo como nombre reservado para documentación.

2. Preparar Windows Server 2022

  1. 1

    Conecte DC01 y los clientes al mismo vSwitch interno o privado. Si necesita descargar actualizaciones, use temporalmente una interfaz externa controlada.

  2. 2

    Instale todas las actualizaciones, seleccione la zona horaria correcta y confirme que el reloj sea preciso.

  3. 3

    Cambie el nombre del servidor a DC01 y reinicie. Hágalo antes de promoverlo.

  4. 4

3. Instalar AD DS y crear el bosque

La instalación gráfica tiene dos etapas diferentes. En la primera se agregan los archivos y herramientas del rol. En la segunda se configura el bosque y el servidor se convierte realmente en controlador de dominio.

Etapa A · Asistente para agregar roles y características

A1
Abrir el asistente

Abra Administrador del servidor. En la esquina superior derecha seleccione Administrar → Agregar roles y características. También puede usar el vínculo del panel principal.

Resultado: se abre el Asistente para agregar roles y características.
A2
Antes de comenzar

Esta pantalla recuerda que el servidor debe tener contraseña administrativa segura, dirección IP configurada y actualizaciones aplicadas. Confirme esos requisitos y pulse Siguiente. La opción para omitir esta página solo afecta futuras aperturas del asistente.

No instale el rol si la IP todavía es dinámica o el nombre definitivo no es DC01.
A3
Seleccionar tipo de instalación

Marque Instalación basada en características o en roles y pulse Siguiente. Esta opción instala roles en un servidor concreto.

No seleccione “Instalación de Servicios de Escritorio remoto”; corresponde a una infraestructura RDS y no a Active Directory.
A4
Seleccionar servidor de destino

Elija Seleccionar un servidor del grupo de servidores. En la tabla marque DC01 y verifique su dirección IP 192.168.10.10. Pulse Siguiente.

La opción “Seleccionar un disco duro virtual” sirve para modificar un VHD/VHDX sin conexión; no se usa en este laboratorio.
A5
Seleccionar roles de servidor

Active Servicios de dominio de Active Directory. Aparecerá una ventana con las herramientas necesarias; pulse Agregar características. Compruebe que el rol queda marcado y pulse Siguiente.

Se agregan, entre otras, las herramientas de administración de AD DS y el módulo de Active Directory para Windows PowerShell.
A6
Seleccionar características

Revise la lista y conserve las selecciones agregadas automáticamente. No necesita marcar características adicionales para este laboratorio. Pulse Siguiente.

No es necesario instalar aquí el rol DNS manualmente: al crear el bosque, el asistente de AD DS lo instalará porque se mantendrá seleccionada la opción Servidor DNS.
A7
Servicios de dominio de Active Directory

Lea el resumen del rol. La página explica que AD DS almacena información de usuarios y equipos, recomienda al menos dos controladores para disponibilidad e indica que DNS es necesario para localizar el dominio. Pulse Siguiente.

Esta pantalla es informativa; si no aparece, regrese y compruebe que seleccionó el rol correcto.
A8
Confirmar selecciones de instalación

Compruebe que aparece Servicios de dominio de Active Directory. Para esta primera etapa puede dejar desmarcada Reiniciar automáticamente el servidor de destino en caso necesario, porque la instalación de los binarios del rol no requiere reinicio. Pulse Instalar.

“Especificar una ruta de origen alternativa” solo se usa cuando el servidor no encuentra los archivos de instalación.
A9
Progreso y resultados

No cierre la ventana hasta ver Instalación correcta en DC01. Luego seleccione Promover este servidor a controlador de dominio. Si cerró la ventana, abra la bandera de notificaciones del Administrador del servidor y seleccione el mismo vínculo.

En este punto el rol está instalado, pero DC01 todavía no es un controlador de dominio.

Etapa B · Asistente para configuración de Servicios de dominio de Active Directory

B1
Configuración de implementación

El asistente ofrece tres posibilidades: Agregar un controlador de dominio a un dominio existente, Agregar un nuevo dominio a un bosque existente y Agregar un nuevo bosque. Como este es el primer controlador, seleccione Agregar un nuevo bosque. En Nombre de dominio raíz escriba ad.empresa.example y pulse Siguiente.

El nombre debe tener al menos dos etiquetas separadas por punto; no escriba solamente “EMPRESA”.
B2
Opciones del controlador de dominio

En Nivel funcional del bosque y Nivel funcional del dominio seleccione Windows Server 2016. En capacidades, mantenga marcados Servidor del Sistema de nombres de dominio (DNS) y Catálogo global (GC). Deje sin marcar Controlador de dominio de solo lectura (RODC).

En Nombre del sitio conserve Default-First-Site-Name para el laboratorio. Escriba y confirme una contraseña robusta para el Modo de restauración de servicios de directorio (DSRM). Pulse Siguiente.

La contraseña DSRM permite recuperar AD DS fuera del funcionamiento normal; guárdela de forma segura y no reutilice la de Administrator.
B3
Opciones de DNS

En un bosque nuevo puede aparecer: “No se puede crear una delegación para este servidor DNS”. En este laboratorio es una advertencia esperada porque no existe una zona DNS padre administrada desde la cual delegar. Pulse Siguiente.

Si está integrando el dominio en una infraestructura DNS corporativa existente, no ignore el aviso: coordine la delegación con el administrador de la zona padre.
B4
Opciones adicionales

Espere mientras el asistente calcula el nombre NetBIOS. Confirme que sea EMPRESA y pulse Siguiente.

NetBIOS se utiliza por compatibilidad y permite iniciar sesión como EMPRESA\usuario.
B5
Rutas de acceso

Para el laboratorio conserve: base de datos C:\Windows\NTDS, archivos de registro C:\Windows\NTDS y SYSVOL C:\Windows\SYSVOL. Pulse Siguiente.

En producción, las rutas pueden ubicarse en volúmenes separados según el diseño de rendimiento, capacidad, copia de seguridad y recuperación.
B6
Revisar opciones

Revise dominio, nivel funcional, DNS, catálogo global, sitio, rutas y NetBIOS. Pulse Ver script si quiere guardar el equivalente de PowerShell para documentación. Después pulse Siguiente.

La contraseña DSRM no se muestra ni se exporta en texto claro.
B7
Comprobación de requisitos previos

Espere a que terminen las pruebas de red, DNS, permisos y configuración. Debe aparecer Todas las comprobaciones de requisitos previos se realizaron correctamente. Lea las advertencias; corrija cualquier elemento marcado como error antes de continuar.

La advertencia sobre delegación DNS puede aceptarse en este bosque nuevo de laboratorio. Una dirección IP dinámica, un error de DNS o un reinicio pendiente sí deben corregirse.
B8
Instalación y reinicio

Pulse Instalar. No apague la VM ni cierre forzosamente la sesión. El asistente crea el bosque, instala y configura DNS, genera SYSVOL/NETLOGON y reinicia DC01 automáticamente.

Después del reinicio, el inicio de sesión cambia de cuenta local a cuenta del dominio EMPRESA.

Las opciones de origen de replicación e instalación desde medios también corresponden a controladores adicionales. No son necesarias al crear este primer bosque.

5. Crear OUs, grupos y usuarios

Las unidades organizativas permiten ordenar objetos y aplicar directivas. Los grupos representan permisos; los usuarios representan personas. Evite asignar permisos recurso por recurso a cada usuario.

  1. 1

    Abra Herramientas → Usuarios y equipos de Active Directory.

  2. 2

    En la raíz del dominio cree la OU Empresa. Dentro cree Usuarios, Equipos y Grupos.

  3. 3

    En Usuarios cree Ana Torres (atorres) y Luis Gómez (lgomez). Use contraseñas temporales únicas y active el cambio en el siguiente inicio.

  4. 4

    En Grupos cree GG-Ventas como grupo Global de Seguridad y agregue a Ana Torres.

  5. 5

    Abra Herramientas → Administración de directivas de grupo. Cree GPO-Base-Usuarios, vincúlela a la OU Usuarios y configure una directiva sencilla, por ejemplo protector de pantalla protegido por contraseña con espera de 900 segundos.

PowerShell · estructura de ejemplo
$base = "DC=ad,DC=empresa,DC=example"
New-ADOrganizationalUnit -Name "Empresa" -Path $base
New-ADOrganizationalUnit -Name "Usuarios" -Path "OU=Empresa,$base"
New-ADOrganizationalUnit -Name "Equipos" -Path "OU=Empresa,$base"
New-ADOrganizationalUnit -Name "Grupos" -Path "OU=Empresa,$base"

$tempPassword = Read-Host "Contraseña temporal" -AsSecureString
New-ADUser -Name "Ana Torres" -SamAccountName "atorres" `
  -UserPrincipalName "atorres@ad.empresa.example" `
  -Path "OU=Usuarios,OU=Empresa,$base" `
  -AccountPassword $tempPassword -Enabled $true `
  -ChangePasswordAtLogon $true

New-ADGroup -Name "GG-Ventas" -GroupScope Global `
  -GroupCategory Security -Path "OU=Grupos,OU=Empresa,$base"
Add-ADGroupMember -Identity "GG-Ventas" -Members "atorres"

6. Instalar y unir dos equipos Windows 11 Pro

Crear e instalar PC-VENTAS01

  1. 1

    En Hyper-V cree una VM Generación 2 llamada PC-VENTAS01: 4 GB RAM, 2 vCPU, VHDX de 64 GB y el mismo vSwitch de DC01.

  2. 2

    Monte una ISO oficial de Windows 11, inicie desde DVD e instale Windows 11 Pro. Cree una cuenta administrativa local para la preparación.

  3. 3

    Instale actualizaciones, cambie el nombre a PC-VENTAS01 y reinicie.

  4. 4

    Configure IP 192.168.10.21/24, gateway 192.168.10.1 y DNS preferido 192.168.10.10.

  5. 5

    Pruebe ping 192.168.10.10 y Resolve-DnsName ad.empresa.example. La resolución DNS debe funcionar antes de unir el equipo.

Crear e instalar PC-TI01

Repita el proceso con IP 192.168.10.22. Si clona una plantilla, ejecute primero sysprep /generalize /oobe /shutdown; no copie directamente un Windows ya configurado y encendido.

Unir ambos equipos al dominio

  1. 1

    Inicie con la cuenta administrativa local. Abra Configuración → Sistema → Información → Configuración avanzada del sistema. En la pestaña Nombre de equipo, pulse Cambiar.

  2. 2

    En Miembro de seleccione Dominio, escriba ad.empresa.example y pulse Aceptar.

  3. 3

    Cuando se solicite, use una cuenta autorizada, por ejemplo EMPRESA\Administrator. En producción use una cuenta con permisos delegados para unir equipos.

  4. 4

    Confirme el mensaje de bienvenida al dominio y reinicie.

  5. 5

    En el inicio de sesión seleccione Otro usuario e ingrese EMPRESA\atorres en PC-VENTAS01. Use EMPRESA\lgomez en PC-TI01.

  6. 6

    En Usuarios y equipos de Active Directory mueva los objetos desde el contenedor Computers a OU=Equipos,OU=Empresa para que reciban las GPO vinculadas.

8. Problemas frecuentes

“No se pudo encontrar el dominio”+

Revise que el DNS del cliente sea 192.168.10.10, no el router ni un DNS público. Pruebe los registros SRV con nslookup -type=SRV _ldap._tcp.dc._msdcs.ad.empresa.example.

La unión pide credenciales repetidamente+

Use EMPRESA\usuario o usuario@ad.empresa.example, confirme permisos de unión y revise %windir%\debug\NetSetup.log.

Kerberos o inicio de sesión falla+

Compruebe fecha, zona horaria y sincronización. Una diferencia de reloj puede impedir la autenticación Kerberos.

La GPO no se aplica+

Mueva el objeto a la OU correcta, ejecute gpupdate /force y revise gpresult /h C:\Temp\gpo.html.

9. Recomendaciones para producción

Disponibilidad

  • Implemente al menos dos DC/DNS.
  • Realice copia de seguridad del estado del sistema.
  • Pruebe restauración y contraseña DSRM.

Seguridad

  • No use Domain Admin para tareas diarias.
  • Delegue la unión de equipos a una OU.
  • Implemente Windows LAPS para administradores locales.

Operación

  • Supervise dcdiag, DNS y eventos.
  • Documente OUs, GPO y grupos.
  • Agregue DNS externos solo como reenviadores.

11
Diagnóstico

Solución de problemas frecuentes

Hyper‑V no aparece en Características de Windows+

Compruebe que Windows sea Pro, Enterprise o Education y de 64 bits. Si es Home, deberá actualizar la edición o usar otra plataforma autorizada.

La máquina virtual no puede iniciar+

Revise que la virtualización esté activa en UEFI/BIOS, que Hyper‑V esté habilitado y que haya memoria disponible. Reduzca la RAM inicial si el host está limitado.

Aparece “No operating system was loaded”+

Confirme que la ISO esté montada, la unidad DVD sea la primera opción de firmware y que presionó una tecla durante el aviso de arranque.

La VM no tiene Internet+

Revise que el adaptador esté conectado al vSwitch externo correcto, que el host tenga conexión y que IP, puerta de enlace y DNS sean válidos. Pruebe primero gateway y luego DNS.

El host perdió temporalmente la red+

Al crear un conmutador externo, Windows reemplaza el enlace directo por un adaptador virtual. Espere unos segundos y confirme que se eligió la NIC física activa y que se permite compartirla con el host.

La instalación muestra solo consola+

Se instaló Server Core. Si necesita interfaz gráfica, repita la instalación y elija una edición que indique Desktop Experience.

El rendimiento es muy lento+

Cierre aplicaciones del host, use SSD, asigne 2 vCPU y al menos 4 GB de RAM, y evite reservar más memoria de la que el host puede sostener.

Administración eficiente

Crear el laboratorio con PowerShell

Este ejemplo reproduce la configuración base. Ejecútelo en PowerShell como administrador y adapte rutas, memoria y nombre del conmutador.

PowerShell · creación completa de la VM
$vmName = "SRV-WS2022-LAB"
$vmPath = "D:\Hyper-V"
$isoPath = "D:\ISO\Windows_Server_2022.iso"
$switchName = "vSwitch-Externo"

# Crear la máquina virtual de generación 2
New-VM -Name $vmName -Generation 2 -MemoryStartupBytes 4GB `
  -NewVHDPath "$vmPath\$vmName\$vmName.vhdx" -NewVHDSizeBytes 80GB `
  -Path $vmPath -SwitchName $switchName

# Ajustar procesador y memoria dinámica
Set-VMProcessor -VMName $vmName -Count 2
Set-VMMemory -VMName $vmName -DynamicMemoryEnabled $true `
  -MinimumBytes 2GB -StartupBytes 4GB -MaximumBytes 8GB

# Montar ISO y priorizar el DVD
Add-VMDvdDrive -VMName $vmName -Path $isoPath
$dvd = Get-VMDvdDrive -VMName $vmName
Set-VMFirmware -VMName $vmName -FirstBootDevice $dvd

# Iniciar
Start-VM -Name $vmName
VMConnect.exe localhost $vmName
!
Antes de ejecutar

Compruebe que las carpetas existen, la ISO es accesible y vSwitch-Externo coincide exactamente con el nombre de su conmutador.
