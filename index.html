1. Comprender Active Directory antes de configurarlo

Active Directory Domain Services (AD DS) es el directorio central de una red Windows. Guarda objetos —usuarios, equipos y grupos— y permite que una persona use una sola identidad para entrar en los equipos y acceder únicamente a los recursos autorizados. Un controlador de dominio es el servidor que conserva esa información y responde a las solicitudes de autenticación.

?
Una comparación sencilla

Imagine una empresa como un edificio: el bosque es toda la organización; los dominios son sedes administrativas; las OU son departamentos; los usuarios son empleados; los grupos representan cargos; los permisos abren puertas; y las GPO establecen reglas comunes.

01

Bosque

Definición: nivel lógico más alto de AD DS; reúne uno o más dominios que comparten esquema, configuración y catálogo global.

Función: establece el gran límite de confianza y administración.

Ejemplo: el primer dominio ad.empresa.example crea también el bosque del laboratorio.

02

Árbol

Definición: uno o más dominios de un bosque cuyos nombres DNS forman una jerarquía continua.

Función: permite crecer conservando relación de nombres.

Ejemplo: ad.empresa.example y sede.ad.empresa.example pertenecerían al mismo árbol.

03

Dominio

Definición: partición del directorio que contiene identidades y equipos y se replica entre sus controladores.

Función: autentica cuentas y aplica reglas comunes.

Ejemplo: el usuario EMPRESA\atorres pertenece a ad.empresa.example.

04

Unidad organizativa (OU)

Definición: contenedor creado dentro de un dominio para ordenar objetos.

Función: facilita delegar administración y vincular GPO.

Ejemplo: OU=Usuarios,OU=Ventas reúne las cuentas del departamento.

05

Grupo

Definición: conjunto de cuentas administradas como una sola identidad de seguridad.

Función: asigna acceso por función laboral, sin configurar usuario por usuario.

Ejemplo: Grupo_Ventas_Comerciales recibe acceso a la carpeta General.

06

Usuario

Definición: objeto que representa a una persona o, en casos controlados, a un servicio.

Función: identifica y autentica mediante nombre y credencial.

Ejemplo: Ana Torres inicia como atorres@ad.empresa.example.

07

Permiso

Definición: regla que autoriza o deniega una acción sobre un recurso.

Función: controla lectura, modificación o administración de carpetas, impresoras y aplicaciones.

Ejemplo: Directivos modifica General y Dirección; Comerciales solo General.

08

Política de grupo (GPO)

Definición: colección central de opciones para usuarios o equipos.

Función: impone configuraciones coherentes según el sitio, dominio u OU donde se vincule.

Ejemplo: bloquear la pantalla de Ventas tras 900 segundos.

!
OU no significa grupo

Una OU organiza y delimita administración o directivas; un grupo concede acceso. Mover a Ana a la OU Ventas no le da permiso sobre una carpeta: debe pertenecer al grupo autorizado.

B3
Opciones de DNS

En un bosque nuevo puede aparecer: “No se puede crear una delegación para este servidor DNS”. En este laboratorio es una advertencia esperada porque no existe una zona DNS padre administrada desde la cual delegar. Pulse Siguiente.

Si está integrando el dominio en una infraestructura DNS corporativa existente, no ignore el aviso: coordine la delegación con el administrador de la zona padre.
B4
Opciones adicionales

NetBIOS se utiliza por compatibilidad y permite iniciar sesión como EMPRESA\usuario.
B5
Rutas de acceso

Para el laboratorio conserve: base de datos C:\Windows\NTDS, archivos de registro C:\Windows\NTDS y SYSVOL C:\Windows\SYSVOL. Pulse Siguiente.

En producción, las rutas pueden ubicarse en volúmenes separados según el diseño de rendimiento, capacidad, copia de seguridad y recuperación.
B6
Revisar opciones

Revise dominio, nivel funcional, DNS, catálogo global, sitio, rutas y NetBIOS. Pulse Ver script si quiere guardar el equivalente de PowerShell para documentación. Después pulse Siguiente.

La contraseña DSRM no se muestra ni se exporta en texto claro.
B7

Espere a que terminen las pruebas de red, DNS, permisos y configuración. Debe aparecer Todas las comprobaciones de requisitos previos se realizaron correctamente. Lea las advertencias; corrija cualquier elemento marcado como error antes de continuar.

Paso 3 · Elegir el reenviador correcto

Los reenviadores son direcciones IP de servidores DNS, no nombres de dominio ni puertas de enlace elegidas al azar. Use solamente una de estas opciones según su escenario:

A
Red de una organización

Solicite al administrador las IP de los DNS corporativos superiores o del proveedor de Internet. Ejemplos internos podrían ser 10.20.0.10 y 10.20.0.11, pero no copie esos ejemplos: use los valores reales entregados por la organización.

Esta es la opción recomendada en producción.
B
Laboratorio doméstico

Puede usar 192.168.10.1 solo si el router actúa como servidor DNS. Compruébelo primero con nslookup microsoft.com 192.168.10.1. Si responde y la política del laboratorio lo permite, esa IP puede ser el reenviador.

Es la opción coherente con la topología de este curso.
C
DNS público permitido

En un laboratorio independiente puede usar, con autorización, Cloudflare 1.1.1.1 o Google Public DNS 8.8.8.8. Son ejemplos de servicios públicos; no pertenecen a Active Directory ni reemplazan el DNS interno.

Nunca los coloque en la tarjeta de red de los miembros del dominio.
D
Laboratorio sin Internet

No configure ningún reenviador. Active Directory, los usuarios, las GPO y los nombres de ad.empresa.example seguirán funcionando dentro de la red aislada.

Solo fallará la resolución de nombres externos.
!
No confunda dos configuraciones diferentes

En la tarjeta IPv4 de DC01, DNS preferido permanece en 192.168.10.10. En los clientes, el DNS también debe ser 192.168.10.10. La IP externa se escribe únicamente en la pestaña Reenviadores del servicio DNS de DC01. Si coloca 1.1.1.1 o 8.8.8.8 en un cliente, ese cliente puede navegar, pero podría no encontrar el dominio.

7. DNS: cómo Active Directory encuentra sus servicios

DNS (Sistema de nombres de dominio) traduce nombres comprensibles, como DC01.ad.empresa.example, en direcciones IP. En Active Directory también publica registros SRV que indican dónde están el controlador, Kerberos y LDAP. Por eso todos los miembros del dominio deben consultar primero al DNS interno y no al router ni a un DNS público.

DNS

Zona DNS

Parte del espacio de nombres administrada por un servidor. La zona ad.empresa.example se crea integrada en AD al promover DC01 y puede replicarse con el directorio.

A

Registro de host (A)

Relaciona un nombre IPv4 con una dirección. Ejemplo: intranet.ad.empresa.example → 192.168.10.30.

MX

Intercambiador de correo

Indica qué servidor recibe correo para un dominio. Ejemplo: prioridad 10 hacia correo.ad.empresa.example. El registro no instala un servidor de correo.

→

Resolución de nombres

Proceso por el cual un cliente pregunta al DNS y recibe el registro solicitado. Si el servidor interno no conoce un nombre de Internet, puede consultarlo mediante reenviadores.

Práctica DNS · Crear una zona inversa y registros A, PTR y MX

1

¿Por qué? esos registros SRV permiten que un cliente encuentre el controlador sin conocer su IP de antemano.

En Tipo de zona seleccione Zona principal, conserve marcada Almacenar la zona en Active Directory y pulse Siguiente. En Ámbito de replicación elija replicar en todos los servidores DNS que se ejecutan en controladores de dominio de este dominio. Seleccione Zona de búsqueda inversa para IPv4. En Id. de red escriba 192.168.10. Seleccione Permitir solo actualizaciones dinámicas seguras y pulse Siguiente → Finalizar.

8. DHCP: entregar la configuración de red automáticamente

DHCP (Protocolo de configuración dinámica de host) entrega a cada cliente una IP y los datos necesarios para comunicarse. El cliente recibe una concesión temporal; al renovarla puede conservar su dirección sin que el administrador configure cada equipo manualmente.

↔

Rango de direcciones

Conjunto que DHCP puede entregar. En el laboratorio: 192.168.10.100–192.168.10.200.

⏱

Concesión

Tiempo durante el cual una IP queda asignada a un cliente. Se usarán 8 días para una red estable; en redes de visitantes conviene un período menor.

003

Puerta de enlace

Opción que indica por dónde salen los clientes a otras redes: 192.168.10.1.

006

Servidores DNS

Opción crítica para el dominio: 192.168.10.10. La opción 015 anunciará ad.empresa.example como sufijo DNS.

!
Alcance del laboratorio

Para ahorrar recursos se instalará DHCP en DC01. En una infraestructura empresarial es preferible separar roles según disponibilidad y seguridad. Si los clientes están en otra VLAN, configure un agente de retransmisión DHCP o IP helper en el enrutador.

En Roles de servidor marque Servidor DHCP; en la ventana emergente pulse Agregar características. En Características no agregue nada más. En la página informativa Servidor DHCP pulse Siguiente. En Confirmación revise que aparezca Servidor DHCP y pulse Instalar. Espere el mensaje de instalación correcta y pulse Cerrar.

11. Problemas frecuentes

“No se pudo encontrar el dominio”+

Revise que el DNS del cliente sea 192.168.10.10, no el router ni un DNS público. Pruebe los registros SRV con nslookup -type=SRV _ldap._tcp.dc._msdcs.ad.empresa.example.

La unión pide credenciales repetidamente+

Use EMPRESA\usuario o usuario@ad.empresa.example, confirme permisos de unión y revise %windir%\debug\NetSetup.log.

Kerberos o inicio de sesión falla+

Compruebe fecha, zona horaria y sincronización. Una diferencia de reloj puede impedir la autenticación Kerberos.

La GPO no aparece como aplicada+

En DC01 abra Usuarios y equipos de Active Directory y confirme que la cuenta está en Empresa → Ventas → Usuarios. Después, en Administración de directivas de grupo, compruebe que GPO-Ventas-Usuarios aparece vinculada debajo de esa misma OU y que Usuarios autenticados conserva los permisos de lectura y aplicación. En el cliente cierre la sesión, vuelva a entrar con una cuenta del dominio, ejecute gpupdate /force y revise gpresult /scope user /r. Para un informe detallado cree primero C:\Temp y ejecute gpresult /h C:\Temp\gpo.html.

Daniel puede abrir la carpeta Direccion+

En DC01 haga clic derecho exactamente sobre C:\Recursos\Ventas\Direccion → Seguridad → Opciones avanzadas. Confirme que Grupo_Ventas_Comerciales, Usuarios y Usuarios autenticados no tengan una entrada Permitir que se aplique a esa carpeta. Use la pestaña Acceso efectivo, seleccione EMPRESA\drojas y consulte su acceso. Después cierre por completo la sesión de Daniel y vuelva a iniciarla para renovar el token de grupos.

Nadie puede abrir \\DC01\Ventas+

En DC01 haga clic derecho sobre C:\Recursos\Ventas → Propiedades → Compartir → Uso compartido avanzado. Confirme que Compartir esta carpeta esté marcado y que el nombre sea Ventas. En Permisos deben aparecer ambos grupos con Cambiar y Leer. Luego revise la pestaña Seguridad: ambos grupos necesitan Lectura y ejecución sobre la carpeta raíz. Desde el cliente pruebe Test-NetConnection DC01 -Port 445; si falla, revise conectividad y las reglas de Compartir archivos e impresoras del firewall.

Windows no encuentra el grupo al agregar permisos+

En la ventana Seleccionar usuarios o grupos pulse Ubicaciones y elija ad.empresa.example, no solo DC01. Pulse Tipos de objeto y confirme que Grupos esté marcado. Escriba el nombre completo, por ejemplo Grupo_Ventas_Directivos, y pulse Comprobar nombres.

El cliente obtiene una dirección 169.254.x.x+

No recibió una concesión DHCP. Confirme que el ámbito esté activo, el servidor autorizado, el servicio iniciado y el cliente conectado al mismo vSwitch o a una red con retransmisión DHCP.

El nombre intranet no resuelve+

Ejecute ipconfig /all y confirme DNS 192.168.10.10. Revise que el registro A exista en la zona correcta, limpie la caché con ipconfig /flushdns y vuelva a consultar.

Escritorio remoto rechaza a Ana+

Cierre y abra la sesión de Ana después de agregarla al grupo, compruebe whoami /groups, valide que el grupo esté en Usuarios de Escritorio remoto y pruebe Test-NetConnection PC-VENTAS01 -Port 3389.

Diagnóstico

Solución de problemas frecuentes

Hyper‑V no aparece en Características de Windows+

Compruebe que Windows sea Pro, Enterprise o Education y de 64 bits. Si es Home, deberá actualizar la edición o usar otra plataforma autorizada.

La máquina virtual no puede iniciar+

Revise que la virtualización esté activa en UEFI/BIOS, que Hyper‑V esté habilitado y que haya memoria disponible. Reduzca la RAM inicial si el host está limitado.

Aparece “No operating system was loaded”+

Confirme que la ISO esté montada, la unidad DVD sea la primera opción de firmware y que presionó una tecla durante el aviso de arranque.

La VM no tiene Internet+

Revise que el adaptador esté conectado al vSwitch externo correcto, que el host tenga conexión y que IP, puerta de enlace y DNS sean válidos. Pruebe primero gateway y luego DNS.

El host perdió temporalmente la red+

Al crear un conmutador externo, Windows reemplaza el enlace directo por un adaptador virtual. Espere unos segundos y confirme que se eligió la NIC física activa y que se permite compartirla con el host.

La instalación muestra solo consola+

Se instaló Server Core. Si necesita interfaz gráfica, repita la instalación y elija una edición que indique Desktop Experience.

El rendimiento es muy lento+

Cierre aplicaciones del host, use SSD, asigne 2 vCPU y al menos 4 GB de RAM, y evite reservar más memoria de la que el host puede sostener.

Administración eficiente

Crear el laboratorio con PowerShell

Este ejemplo reproduce la configuración base. Ejecútelo en PowerShell como administrador y adapte rutas, memoria y nombre del conmutador.

PowerShell · creación completa de la VM
$vmName = "SRV-WS2022-LAB"
$vmPath = "D:\Hyper-V"
$isoPath = "D:\ISO\Windows_Server_2022.iso"
$switchName = "vSwitch-Externo"

# Crear la máquina virtual de generación 2
New-VM -Name $vmName -Generation 2 -MemoryStartupBytes 4GB `
  -NewVHDPath "$vmPath\$vmName\$vmName.vhdx" -NewVHDSizeBytes 80GB `
  -Path $vmPath -SwitchName $switchName

# Ajustar procesador y memoria dinámica
Set-VMProcessor -VMName $vmName -Count 2
Set-VMMemory -VMName $vmName -DynamicMemoryEnabled $true `
  -MinimumBytes 2GB -StartupBytes 4GB -MaximumBytes 8GB

# Montar ISO y priorizar el DVD
Add-VMDvdDrive -VMName $vmName -Path $isoPath
$dvd = Get-VMDvdDrive -VMName $vmName
Set-VMFirmware -VMName $vmName -FirstBootDevice $dvd

# Iniciar
Start-VM -Name $vmName
VMConnect.exe localhost $vmName
!
Antes de ejecutar

Compruebe que las carpetas existen, la ISO es accesible y vSwitch-Externo coincide exactamente con el nombre de su conmutador.
